# 사전등록 — Claude 만 vs WALP 앞단 + Claude (토큰 · 응답 시간)

봉인 요청 모음을 열기 **전에** 커밋한다. 결과는 맨 아래 '결과' 에만 덧붙인다.

## 물음

worldplan 의 도우미(`/api/assistant`)에서, Claude 앞에 WALP 를 세우면 토큰과 응답 시간이 얼마나 주는가.
그리고 그 대가로 앞단이 얼마나 틀리는가.

## 선행 — 새것이 아니다

LLM 앞에 싼 층을 두고 쉬운 것만 거기서 끝내는 것은 이미 있는 생각이다. 아래는 **기억으로 적은 목록이고,
이번에 다시 읽지 않았다** [출처:목록].

- LLM cascade · 라우터: FrugalGPT(Chen 외 2023, arXiv:2305.05176), RouteLLM(Ong 외 2024, arXiv:2406.18665)
- 의미 캐시: GPTCache
- 대화 시스템의 의도 분류 + 폴백(Rasa 등)
- SE 저장소의 `paper/선행조사/WALP_LLM앞단.md` (같은 구조를 WALP 안에서 잰 것)

여기서 재는 것은 **이 앱에서 이 앞단이 얼마를 아끼는가** 하나다. 일반론은 주장하지 않는다.

## 조건

같은 `ClaudeCLI`(`claude -p --output-format json`, CLI 기본 모형, worldplan MCP 도구만, 짧은 시스템 프롬프트,
빈 작업 폴더, 현재 요청 = `static/sample.json`)를 쓴다.

| | 앞단 | Claude |
|---|---|---|
| **C** | 없음 | 모든 말 |
| **W** | 시각 센서(`clock_answer`) → WALP 행동 버스(SE `walp`, 학습 체계 `base_seed1.json`): 잡담 6부류면 끝 | 나머지 |
| **R** (대조, Claude 를 따로 안 부름) | 시각 센서 → **낱말 목록**(`assist_compare.KEYWORDS`) | 나머지 — C 에서 잰 값을 쓴다 |

R 은 "WALP 가 낱말 몇 줄보다 나은가" 를 본다. 시각 센서는 W 와 R 에 똑같이 들어 있다.

## 재는 것

- 토큰: 요청당 `input + cache_creation + cache_read + output` (CLI 의 `usage`). 앞단이 답하면 0
- 비용: CLI 의 `total_cost_usd`
- 응답 시간: `Assistant.ask` 의 벽시계(ms). CLI 띄우는 시간이 들어간다 — API 시간(`duration_api_ms`)도 같이 적는다
- 앞단 오답: 앞단이 답했는데 (a) 그 말의 부류가 잡담/시각이 아니었거나 (b) 시각이 틀렸다(정답 ±0분, '지금' 은 ±2분)
- 시각 정답률: clock 부류에서 답에 정답 시각이 들어 있나(오전/오후 없는 'N시' 는 두 뜻 다 인정 — 두 조건에 같게)

요청마다 C 와 W 를 **무작위 순서로 붙여** 돌린다(seed 20261001) — 캐시 데움 · 시간 표류를 둘이 같이 받는다.

## 가설과 결정

- **H1** 토큰: 요청당 (W − C) 평균의 단측 95% 부트스트랩 상한 < 0
- **H2** 시간: 요청당 (W − C) ms 평균의 단측 95% 부트스트랩 상한 < 0
- **H3** 안전: W 의 앞단 오답률 ≤ 5% (Wilson 단측 95% 상한도 같이 적는다)
- **결정:** H1 과 H3 이 서면 앱의 도우미는 앞단을 켠 채로 낸다. H3 이 안 서면 끈다 — 아끼는 것보다 틀리는 것이 먼저다

## 사소한 설명 — 재서 죽일 것

1. **아낀 것이 CLI 띄우는 시간뿐** → 토큰(띄우는 시간과 무관)과 API ms 를 따로 본다
2. **앞단이 틀리게 답해서 아낀 것** → H3, 그리고 부류별 앞단 오답
3. **WALP 가 아니라 낱말 몇 줄로도 된다** → R 대조. W 와 R 의 앞단 처리 수 · 오답 수를 나란히
4. **두 조건이 Claude 로 보낸 같은 말에서 차이가 난다(측정 잡음)** → 둘 다 Claude 로 간 줄만 모아 (W − C) 평균이 0 근처인지(독립 대조)
5. **섞임 탓** → 부류별 수. 실제 섞임 p(부류) 를 알면 기대 절감 = Σ p · (부류별 C 평균 − W 평균)

## 무효화

모형이 바뀌면 · CLI 의 시스템 프롬프트 크기가 바뀌면 · Claude 를 API 로 직접 부르면(띄우는 시간이 없어진다) ·
실제 섞임이 잡담 · 시각 쪽으로 덜 치우치면 — 절감은 다시 재야 한다.
